# Job Scrape

원티드·점핏에서 웹 백엔드·서버 개발 공고를 선별한 뒤, 본문과 기술스택에서 Java·Python·Go 등의 수요를 비교하는 웹 앱입니다.

## 실행

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/uvicorn backend.app:app --port 8000 --reload
```

브라우저에서 `http://127.0.0.1:8000`을 엽니다. 8000번 포트가 이미 사용 중이면 `--port 8001`처럼 다른 포트를 지정합니다. 수집에는 Chromium 설치가 필요하지 않습니다.

첫 수집은 사이트별로 이전 응답이 끝난 뒤 1초 이상 기다리고 다음 요청을 보내므로 수분이 걸릴 수 있습니다. 이후에는 캐시를 즉시 분석하며, 새로고침 시 24시간 이내에 확보한 상세 본문을 재사용합니다. 사이트별 새로고침 간격은 1시간입니다.

수집 후 1시간 이내에 새로고침을 누르면 재수집 대기 안내와 함께 저장된 데이터로 분석합니다. 이는 수집 실패가 아니며, 화면에 사이트별 수집 완료 건수·수집 시각·다음 수집 가능 시각을 표시합니다. 실제 사이트 접근 제한이나 통신 오류는 별도 주의사항으로 표시합니다.

## 수집·분석 범위

- 원티드의 `서버 개발자` 직무(872), 점핏의 `서버/백엔드 개발자` 직무(1)를 요청합니다. 특정 언어나 프레임워크로 공고를 선별하지 않습니다.
- 제목에 프론트엔드·풀스택·게임·DevOps/SRE·데이터 엔지니어·임베디드·펌웨어 등 다른 직무가 명시된 공고는 제외합니다. 직무 분류와 제목을 먼저 확인하고 기술은 선별 후 집계합니다.
- 본문이 없는 공고는 통계에서 제외합니다. 기본 화면에서는 마감 공고도 제외하며, 경력 범위와 마감 포함 여부는 조회할 때 적용합니다.
- 전체 분석에서는 회사·제목·경력 범위·근무지가 일치하는 타 사이트 공고를 보수적으로 통합합니다. 통합된 공고의 출처는 목록에 함께 표시합니다.
- 잡코리아·사람인은 현재 API와 화면의 수집 대상에서 제외했습니다. 기존 수집기와 저장 데이터는 보존합니다.

사이트 화면에서 사용하는 목록 응답과 공개 상세 페이지를 읽습니다. 외부 연동을 보장하는 공식 API 계약이 아니므로 응답 형식 변경이나 요청 제한이 발생할 수 있습니다. 통계는 두 사이트에서 본문을 확보한 백엔드 공고의 기술 언급 비율이며 전체 채용시장의 점유율을 뜻하지 않습니다.

## 캐시와 실패 처리

현재 범위는 `backend/cache_wanted_backend.json`, `backend/cache_jumpit.json`에 저장합니다. 기존 `backend/cache.json`은 새 원티드 캐시가 없을 때 읽기 전용으로 사용하며, 백엔드에 해당하는 공고만 조회합니다. 기존 잡코리아·사람인 JSON 및 Markdown은 수정하지 않습니다.

일부 상세만 실패하면 해당 공고의 기존 본문을 재사용하거나 캐시가 없는 공고만 제외합니다. 상세 조회가 모두 실패하거나 다수 실패하면 이전 캐시와 수집 시각을 보존합니다. HTTP 401·403·429는 사이트 단위 오류로 처리해 이후 공고를 계속 요청하지 않습니다. 전체 분석에서 한 사이트가 실패해도 다른 사이트와 사용 가능한 캐시로 분석을 완료합니다.

완료 화면에 사이트별 상세 수집·재사용·제외 건수와 중복 통합 건수를 표시합니다. 24시간이 지난 캐시, 수집 범위·키워드 버전이 다른 캐시, 상세 실패가 있는 데이터에는 주의사항을 표시합니다.

조회 시 기술은 제목·주요 업무·자격 요건·우대 사항·사이트 기술스택에서 다시 계산합니다. 회사 소개·복지와 Markdown 자동 생성 메타데이터는 기술 근거에서 제외하며, 섹션 구분이 없는 기존 본문은 그대로 분석합니다. 경력 필터의 `10`은 10년 이상입니다. 날짜만 있는 마감일은 한국 시간 해당 날짜 23:59:59까지 포함하며, 종료 상태인 공고는 미래 마감일이 있어도 제외합니다.

화면의 분석 시각은 계산을 수행한 시각이며, 데이터 수집 시각과 별도로 표시합니다. 과거 상세 실패는 해당 수집 시각이 적힌 저장 기록으로 표시합니다. 분석 근거가 바뀌었으므로 이전 집계와 기술별 건수가 달라질 수 있습니다.

연결이 끊겨도 서버의 수집은 계속됩니다. 클라이언트는 작업 ID로 원래 결과와 주의사항을 복구합니다. 서버가 재시작됐거나 작업 기록이 없으면 사용 가능한 캐시만 읽으며 자동으로 새 수집을 시작하지 않습니다. 최근 완료 작업 10개의 결과를 메모리에 유지합니다.

- `GET /scrape?cache_only=true`: 외부 요청 없이 저장 데이터만 분석합니다. 일부 사이트의 캐시가 없으면 사용 가능한 사이트로 완료하며, 전부 없으면 SSE 오류를 반환합니다.
- `GET /scrape-status?source=all&run_id=...`: 해당 작업의 진행 여부와 완료 결과를 조회합니다. 작업 ID는 수집 시작 SSE의 `started` 이벤트로 전달됩니다.

## 키워드와 캐시 재생성

`모든공고md`에서 프로그램 전용 키워드 파일을 다시 만들고 현재 원티드·점핏 캐시를 재분석합니다. 같은 공고의 Markdown이 여러 개면 가장 최근 파일을 선택하며, 본문을 더 최근에 수집한 캐시가 있으면 보존합니다. 재분석은 외부 사이트에 요청하지 않으며, 원래 수집 시각을 기준으로 `D-2` 같은 상대 마감일을 해석합니다.

```bash
.venv/bin/python -m backend.build_backend_keywords
.venv/bin/python -m backend.reindex_markdown_cache
```

런타임은 [`backend/data/backend/backend_keywords.json`](backend/data/backend/backend_keywords.json)의 활성 키워드를 사용합니다.

## 구조

```text
backend/
  app.py                    API, 캐시, 수집 작업 조정
  analytics.py              경력 필터, 중복 통합, 기술 통계
  keyword_catalog.py        런타임 키워드 로딩과 추출
  wanted_scraper.py         원티드 서버 개발자 직무 수집
  jumpit_scraper.py         점핏 서버/백엔드 직무 수집
  scrape_http.py            요청 간격, 재시도, 요청 제한 처리
  markdown_export.py        공고별 Markdown 저장
  build_backend_keywords.py 키워드 파일 생성 명령
  reindex_markdown_cache.py 현재 캐시 재분석 명령
frontend/                    웹 화면
모든공고md/                 공고별 원문 및 기존 수집 자료
```

## 검증

```bash
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m unittest discover -s tests -v
```

테스트는 실제 채용 사이트에 요청하지 않습니다. 직무 선별과 기술 집계의 분리, 페이지 순회, 점핏의 긴 본문 파싱, 중복 통합, 요청 제한·캐시 복구, 마감·경력 필터를 검증합니다. 화면 검증에 Playwright를 사용하려면 `.venv/bin/python -m playwright install chromium`으로 브라우저를 설치할 수 있습니다.

브라우저 회귀 검사는 외부 요청을 차단한 로컬 페이지에서 연결 복구·경력 슬라이더·날짜·모바일 레이아웃을 확인합니다.

```bash
.venv/bin/python -m playwright install chromium
.venv/bin/python -m unittest discover -s tests -p browser_checks.py -v
```
